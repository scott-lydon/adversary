The problem this addresses

Static jailbreak lists go stale. Manual penetration tests find one bug and stop. The Clinical Co-Pilot will keep shipping commits, and attacker techniques will keep mutating. A point-in-time security test cannot answer "is this still fixed three commits later?"

Current state without Adversary

Quarterly manual red team

  • • 30 hand-curated jailbreak payloads in a spreadsheet
  • • Run once per quarter, manually reviewed
  • • No mutation, no variants probed
  • • Findings re-tested once at fix time, then never again
  • • No coverage matrix; gaps are invisible
  • • Cannot answer "is this still fixed?" after a commit
With Adversary

Continuous multi-agent red team

  • • Red Team Agent generates novel attacks from seeds
  • • Mutation tree explores variant space automatically
  • • Independent Judge Agent emits structured verdicts
  • • Every confirmed exploit becomes a regression test
  • • Regression replays on every target deploy
  • • Coverage matrix surfaces uncovered categories

The four agents

Each agent has one job. Each runs on a deliberately chosen model. Each is isolated by vendor or by process from the others where independence matters.

🧭 Orchestrator

gpt-5-mini

Strategic planner. Reads coverage matrix, open findings, budget. Picks the next campaign with a weighted choice over category priority.

✓ Pros
  • • Cheap planning at ~$0.01/campaign
  • • Reads SQL, no extra context
  • • Halts on budget exhaustion
✗ Cons
  • • Quality bound by gpt-5-mini reasoning
  • • Brittle to malformed coverage rows
  • • Cannot rationalize tie-breaks well

⚔️ Red Team

Llama 3.1 70B

Attack generator and mutator. Generates novel adversarial inputs and mutates partial successes through 5 transformation families.

✓ Pros
  • • Will engage with offensive prompts
  • • ~8x cheaper than gpt-5
  • • Open weights, auditable
  • • Together AI ~600 req/min ceiling
✗ Cons
  • • Lower instruction-following than gpt-5
  • • Refuses ~5% of prompts (less than frontier)
  • • Mutation creativity bounded by training

⚖️ Judge

Claude Sonnet 4.6

Independent evaluator. Different vendor than Red Team (non-negotiable). 10% of verdicts double-judged by Azure OpenAI for drift detection.

✓ Pros
  • • Vendor-independent from attacker
  • • Strong semantic comprehension
  • • Structured rubric per category
  • • Drift detection built in
✗ Cons
  • • ~94% accuracy on calibration set
  • • Most expensive per-token agent
  • • Anthropic rate limits gate throughput

📝 Documentation

gpt-5

Converts confirmed exploits to professional-grade vulnerability reports. Only fires on confirmed exploits; critical-severity gated by human approval.

✓ Pros
  • • Report quality is the final artifact
  • • Single-shot generation per finding
  • • Reproducible from report alone
✗ Cons
  • • Highest per-call cost ($0.30/report)
  • • Quality depends on Judge's evidence
  • • False positives waste eng time

Key architectural decisions

Every decision is deliberate and traceable to a constraint in the threat model or a PRD requirement. The alternatives I considered are listed honestly.

DecisionWhat I choseAlternative consideredWhy I picked it
Red Team model Llama 3.1 70B (Together) gpt-5 with red-team system prompt Frontier models refuse the most dangerous payloads. Llama produces realistic content.
Judge vendor Anthropic (Claude Sonnet 4.6) Same vendor as Red Team Vendor independence is non-negotiable. Same vendor creates correlation I cannot reason about.
Orchestrator model gpt-5-mini gpt-5 reasoning tier Planning task fits a small model. gpt-5 here is cost without quality gain.
Documentation model gpt-5 gpt-5-mini, Claude Sonnet Report quality is the final artifact. Senior engineers reproduce bugs from this alone.
LLM abstraction LiteLLM Direct vendor SDKs, LangChain Multi-vendor agnostic. Swap any model with a one-line config change.
Orchestration framework LangGraph CrewAI, AutoGen, Temporal, hand-rolled Cohort already uses it. Nodes are plain Python so swap cost is bounded.
Target boundary TargetAdapter ABC Hard-coded to Co-Pilot Reusability across products. New product = ~150 LOC adapter.
Regression replay Deterministic Python LLM-driven replay No reasoning needed for HTTP+JSON. LLM here is unnecessary cost.
Verdict scoring LLM Judge + structural evidence check Exact-string match on response Exact-match passes when wording changes for the wrong reason.
Audit log Hash-chained Postgres + external anchor Append-only file, simple SQL Tamper-evident audit chain is what auditors and CISOs need.

Honest trade-offs

No architecture is free. These are the costs I accepted, and what would have to change for them to bite.

Trade-off 1

Vendor independence costs money and complexity

Three vendors (Together, Anthropic, OpenAI) means three billing relationships, three rate-limit ceilings, three failure modes when one has an incident.

Why I accept it: the Judge being on a different vendor than the Red Team is non-negotiable. A single-vendor system has correlation I cannot reason about.

When it would bite: if Anthropic has a multi-hour outage during a critical regression run. Mitigated by Azure OpenAI Judge fallback wired in but not auto-triggered.

Trade-off 2

Judge accuracy is bounded

Claude Sonnet 4.6 scores ~94% on the calibration set. That means ~6 in 100 verdicts are wrong, in either direction.

Why I accept it: 94% with drift detection is better than 100% with no validation. The platform surfaces its own confidence.

When it would bite: a CISO presenting Adversary numbers to a board needs to lead with "94% Judge accuracy" not "we found 12 exploits."

Trade-off 3

Cost amplifies at scale

Per-campaign cost measured 2026-05-14 is $0.041 (40x cheaper than the original $1.50 projection). At 100K campaigns/month the platform's projected cost lands in the low four figures, not five.

Why I accept it: the current cohort scale is <1K campaigns/month, well within budget. Architectural changes at higher scale are documented.

When it would bite: if the platform is adopted by a multi-hospital network running 10K+ campaigns/day. Requires Judge distillation to local model.

Trade-off 4

LangGraph dependency

Orchestration framework lock-in. If LangGraph deprecates or pivots, refactor cost.

Why I accept it: every node is a plain Python async function. The framework is a thin coordinator, not a runtime.

When it would bite: if LangGraph introduces a breaking API change in a minor version. Swap to Temporal or hand-rolled is a 1-week refactor.

Trade-off 5

Target boundary loses some attack surface

The TargetAdapter ABC is HTTP-shaped. Targets that expose WebSockets, Server-Sent Events, or gRPC need adapter-specific work.

Why I accept it: 95% of LLM products today are HTTP+JSON. Premature generalization to streaming protocols would slow MVP.

When it would bite: attacking a real-time voice assistant. Requires extending the ABC with streaming methods.

Trade-off 6

No write-tool attack coverage

The Co-Pilot has only read-only tools today. Adversary's tool-misuse campaigns are bounded by that.

Why I accept it: attacking surfaces that don't exist would produce noise.

When it would bite: when the Co-Pilot adds order entry or chart-write tools. The threat model already anticipates this; the platform extends naturally.

Cost model: why these models

Per-campaign cost broken down by agent. The Red Team and Judge dominate. Picking gpt-5 for Red Team would multiply platform cost by roughly 8x for marginal quality gain.
